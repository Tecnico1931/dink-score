# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- This repo is the fork `Tecnico1931/dink-score`. An `upstream` remote points at `Campbell11111/dink-score`: never push, PR or comment there. PRs go to the fork's `main` only (`--repo Tecnico1931/dink-score --base main`); merging to `main` redeploys production.
- Source is `dink-score.html` (page body only); `index.html`, `public/` and the CSP hashes in `vercel.json` are generated by `node build.cjs`. Rebuild after every HTML change, bump `VERSION` in `sw.js`, and restart `tools/serve.cjs` (it reads `vercel.json` once, so stale hashes block the inline scripts).
- `npm test` runs the pure event logic (`api/_rotation.js`, `_schedule.js`, `_bracket.js`, `_events.js`) with no install. `tools/api-check.mjs` runs the API against a throwaway in-memory Postgres (needs `npm i --no-save @electric-sql/pglite`). The production Neon database is never used for testing; schema changes must stay additive (`CREATE ... IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS` in `api/_db.js`).
- The bracket drawing (`BK`, inside `<script id="bracketview">` between the `BRACKETVIEW-START/END` markers), its CSS (`BRACKET-CSS-START/END`) and the colour tokens (`TOKENS-START/END`) are shared: `build.cjs` pastes them into `bracket-public.html` to make the public page `b.html` (`/b/<token>`). `test/bracketview.test.js` loads the same block, so keep it free of app globals. Public data may only leave through `publicView()` in `api/_share.js`.
- Event matches reach the club record only through `api/events.js`, with the game id `<eventId>-<matchId>` and `ON CONFLICT DO NOTHING`; the client never saves an event match as a normal game, which is what keeps ratings from double counting.
- DUPR (`api/dupr.js`, `_duprapi.js`, `_dupr_map.js`, `_dupr_store.js`) is feature-flagged off by env (`DUPR_CLIENT_KEY`/`DUPR_CLIENT_SECRET`) and was only ever tested against `tools/dupr-mock.mjs`; `npm test` (`test/duprmap.test.js`) and `node tools/dupr-check.mjs` cover it. Never call real DUPR hosts or keep user tokens; DUPR data stays out of `/api/club`, events and the public bracket. `_dupr.js` is the separate self-reported rating helper.

- Sheet import: `sheet-import.js` (top level, shared by browser and API) parses and checks; `api/_gsheet.js` is the only server fetch of an organizer-supplied link (Google hosts only). Team names/logos live in `event.teamInfo`; DUPR IDs only in `events.refs`, never in `data` or `publicView()`. Logos are https-only (`img-src https:` in the CSP) and the public page shows them only when `publicLogos` is true.
- Organizer-only actions use `requireOrganizer` (creating phone's token or the PIN); a club without a PIN is organized only by its creating phone.
- Club codes rotate: `clubs.code` is the permanent key and `requireClub` (`api/_db.js`) resolves the typed code (current `public_code` or an unexpired `club_aliases` row) to it; handlers must query with `club.code`, never the code from the request. New clubs always get a PIN (generated if none given).
- Never put production identifiers (real club names or codes, organizer PINs or tokens, database or deploy URLs with secrets) in committed files, tests, PR text or issues; use made-up values.
