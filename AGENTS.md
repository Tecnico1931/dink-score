# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- This repo is the fork `Tecnico1931/dink-score`. An `upstream` remote points at `Campbell11111/dink-score`: never push, PR or comment there. PRs go to the fork's `main` only (`--repo Tecnico1931/dink-score --base main`); merging to `main` redeploys production.
- Source is `dink-score.html` (page body only); `index.html`, `public/` and the CSP hashes in `vercel.json` are generated by `node build.cjs`. Rebuild after every HTML change, bump `VERSION` in `sw.js`, and restart `tools/serve.cjs` (it reads `vercel.json` once, so stale hashes block the inline scripts).
- `npm test` runs the pure event logic (`api/_rotation.js`, `_schedule.js`, `_bracket.js`, `_events.js`) with no install. `tools/api-check.mjs` runs the API against a throwaway in-memory Postgres (needs `npm i --no-save @electric-sql/pglite`). The production Neon database is never used for testing; schema changes must stay additive (`CREATE ... IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS` in `api/_db.js`).
- The bracket drawing (`BK`, inside `<script id="bracketview">` between the `BRACKETVIEW-START/END` markers), its CSS (`BRACKET-CSS-START/END`) and the colour tokens (`TOKENS-START/END`) are shared: `build.cjs` pastes them into `bracket-public.html` to make the public page `b.html` (`/b/<token>`). `test/bracketview.test.js` loads the same block, so keep it free of app globals. Public data may only leave through `publicView()` in `api/_share.js`.
- Event matches reach the club record only through `api/events.js`, with the game id `<eventId>-<matchId>` and `ON CONFLICT DO NOTHING`; the client never saves an event match as a normal game, which is what keeps ratings from double counting.
- DUPR (`api/dupr.js`, `_duprapi.js`, `_dupr_map.js`, `_dupr_store.js`) is feature-flagged off by env (`DUPR_CLIENT_KEY`/`DUPR_CLIENT_SECRET`) and was only ever tested against `tools/dupr-mock.mjs`; `npm test` (`test/duprmap.test.js`) and `node tools/dupr-check.mjs` cover it. Never call real DUPR hosts or keep user tokens; DUPR data stays out of `/api/club`, events and the public bracket. `_dupr.js` is the separate self-reported rating helper.

- Sheet import: `sheet-import.js` (top level, shared by browser and API) parses and checks; `api/_gsheet.js` is the only server fetch of an organizer-supplied link (Google hosts only). Team names/logos live in `event.teamInfo`; DUPR IDs only in `events.refs`, never in `data` or `publicView()`. Logos are https-only (`img-src https:` in the CSP) and the public page shows them only when `publicLogos` is true.
- Organizer-only actions use `requireOrganizer` (creating phone's token or the PIN); a club without a PIN is organized only by its creating phone.
- Club codes rotate: `clubs.code` is the permanent key and `requireClub` (`api/_db.js`) resolves the typed code (current `public_code` or an unexpired `club_aliases` row) to it; handlers must query with `club.code`, never the code from the request. New clubs always get a PIN (generated if none given).
- Never put production identifiers (real club names or codes, organizer PINs or tokens, database or deploy URLs with secrets) in committed files, tests, PR text or issues; use made-up values.
- Optional accounts: `api/account.js` + `api/_webauthn.js` (own minimal passkey code, node:crypto only, no dependency). Session cookie `__Host-dink_session` (hash stored); RP ID/origin per request: the `Origin` header must be in `WEBAUTHN_ORIGINS` (comma-separated, RP ID = its hostname; unset = legacy single pair `WEBAUTHN_RP_ID`/`WEBAUTHN_ORIGIN`, see `resolveRp`). `passkeys.rp_id` (null = legacy RP ID) pins a passkey to the address it was made on; cookies are per host, so another address adds a passkey through a one-time `passkey-code`/`handoff-*` code. No-login paths never read these tables. `node tools/account-check.mjs` (PGlite, software authenticator in `tools/fake-authenticator.mjs`) runs in CI.
- Replay: a live game's rally log (`"<first>:<winners>"`, see `api/_rallylog.js`) lives in `games.rally_log`, never in `data` or the club payload (games just get `replay: true`; `GET /api/games?id=` returns the log). `_rallylog.js` is the server's copy of the `PB.rally` rules, pinned to PB by `test/rallylog.test.js`; a bad log is dropped, the game is kept. Edits keep a log only if it still replays to the edited game; event score corrections clear it.
- Player names: `nameKey` (`api/_names.js`: trim, collapse spaces, NFC, lower case) is the only way to key a name; `similarNames` drives the "did you mean" 409 (`similar` in the body, retry with `confirmNew: true`). Rename/merge (`api/players.js` + `api/_rename.js`, organizer only) rewrite every place a name is stored in one transaction and leave a `name_changes` row that phones follow through `renamed` in `GET /api/club`. A new place that stores a player name must be added to `_rename.js`.
- Confirmation/duplicates/audit: rules in `api/_confirm.js` (pure), history written only through `api/_audit.js` (append-only `game_audit`, organizer-only read via `GET /api/games?audit=1`). `hold` on a game means the club setting `require_confirmation` keeps it out of ratings; the client filters with `ratedGames()`.
- Data rights: `api/players.js` (`export`, `anonymise`: one random `Former player XXXXX` label via `_privacy.js`, roster row deleted, games kept) and `api/club.js` (`export`, `delete-club`: sets `clubs.delete_at` 24h ahead, `cancel-delete-club`; `requireClub` and the `purgeMarks` sweep remove expired clubs, children cascade; only the creating phone or the PIN may delete, not a co-organizer; anonymise also relabels `game_audit`, `club_audit` and `name_changes`). New per-club tables must cascade from `clubs` or be added to the rights check. `node tools/rights-check.mjs` runs in CI; `privacy.html` must stay in step.
- Open play court board: pure rules in `api/_court.js` (`test/court.test.js`), storage in `court_boards` (one JSON row per club, version-guarded), routes `board-*` and `GET /api/live?board=1` handled in `api/_courtboard.js` through `live.js` (no new function; the Vercel function count is at its limit). The board never saves a game (the scorer's normal save does), takes a court's winner from the matching live game when there is one, and stores names, so `_rename.js` and anonymise (`players.js`) rewrite it. It is shown on the `/?display=CODE` page.
- Public result pages: `api/_resultsadmin.js` (called from `api/club.js` as `results-*` actions; organizer setting `clubs.public_results`, off by default; members create, organizers list/revoke; `result_shares` rows, turning the setting off deletes them) and `api/_resultpublic.js` (called from `api/bracket.js` with `?result=1`; public, token only, 60/min per network, 20 s edge cache). Output only through `api/_result.js` allow-lists; the card PNG is drawn by `api/_card.js` (own 5x7 font, no image dependency). `/r/<token>` and `/r/<token>/card.png` are rewrites in `build.cjs`; `r.css`/`r.js` are built from `result-public.css`/`result-view.js` plus the shared `REPLAYCHART` blocks of `dink-score.html`. The hosting plan allows 12 serverless functions: never add a non-underscore `api/*.js` (`test/functions.test.js`); fold routes into an existing one. Never add club code/name or ids to that view.

- Accessibility: tokens and court colours are pinned by `test/contrast.test.js` (WCAG ratios), so a colour change that drops a pair fails `npm test`; `tools/a11y-check.mjs` (axe, 44 px, 12 px, reflow; local Chrome, not CI) covers the rest. The per-device outdoor display is `pb.display` (`data-outdoor`/`data-large` on `<html>`, CSS between `A11Y-START/END`). Announce through `announce()` (persistent `#a11y-live`), never a live region inside the court, which is rebuilt every rally. Details in `docs/accessibility.md`.
